# Modified webmscore corresponding source

This directory contains the GPL-3.0-only changes to LibreScore/webmscore used by
the qualified Music Sheets renderer candidate. It is separate from the Apache-2.0
standalone interpreter. This source publication does not announce a Hub release
or claim that the candidate is deployed to Android or the desktop worker.

The [reverse-slur source adoption record](adoptions/reverse-slur-20261014.json)
identifies the newer bundle committed to Music Sheets source after full
generated-style HTML qualification. Reconstruct that bundle by applying the
parent patch below, then the supplemental patch in
`unreleased/reverse-slur-completion`. The original parent manifest describes its
original bundle; it is retained unchanged. Packaged Android/device and desktop
rollout checks remain pending. This source update creates no Hub release.

## Reconstruct the complete source

The separate [articulation/ornament importer draft](unreleased/articulation-ornament-import/README.md)
is queued for a later renderer build. It is not part of the existing adopted
bundle or its corresponding-source manifests.

The subsequent [ornament auxiliary accidental draft](unreleased/ornament-auxiliaries/README.md)
adds retained plain-ornament fields and collision bounds. It also remains separate
from the adopted bundle pending the final renderer build and runtime checks.

The [plain-ornament auxiliary playback draft](unreleased/ornament-auxiliary-playback/README.md)
then connects those retained signs to legacy MIDI ornament pitches. It has source
controls and syntax evidence; rebuilt renderer/runtime verification is pending.

The [delayed-turn draft](unreleased/delayed-turn/README.md) then preserves native
delay identity, places the glyph between note positions and reserves a principal
lead before legacy MIDI turn notes. It also awaits final renderer qualification.

Clone https://github.com/LibreScore/webmscore and check out commit
`78db5eb5437ccf1d17e0c4820374ee12f8862ce9`. Initialize its pinned submodules
with `git submodule update --init --recursive`. From that checkout, apply this
directory's `corresponding-source.patch` with `git apply`. The original tree,
submodules and this patch form the complete modified source. `manifest.json`
records every modified UTF-8/LF source hash and the pinned submodule entries.
`COPYING` preserves the upstream GPL text; upstream copyright and dependency
notices remain in the reconstructed source.

On Windows, Git may check out font metadata symlinks as text. Materialize the five
`metadata.json` links from the same-directory targets listed in the manifest.
Their contents are unchanged upstream data; CRLF normalization is recorded.

## Build

Follow the pinned upstream README's compiling instructions: Emscripten 2.0.6,
Qt 5.15.2 wasm_32 with the upstream `build/qt` overlay and upstream emcc separate
memory-file patch. Initialize all submodules before compiling. Install the
`web-public` package's dependencies using its lockfile. The qualified build used
Node 24.19.0 and Ninja, with these CMake settings:

```text
CMAKE_BUILD_TYPE=RELEASE
EMBED_PRELOADS=OFF
CMAKE_BUILD_NUMBER=78db5eb-baseline
CMAKE_PREFIX_PATH=<Qt 5.15.2 wasm_32 directory>
CMAKE_TOOLCHAIN_FILE=<emsdk>/upstream/emscripten/cmake/Modules/Platform/Emscripten.cmake
```

Configure the patched `web` directory into a separate build directory using the
Emscripten toolchain and Ninja, then build it. Copy the generated library files
into `web-public`, renaming `webmscore.lib.js.mem` to
`webmscore.lib.mem.wasm`; run the package's Rollup bundle task for `webmscore.js`.
The manifest records the four exact qualified browser bundle files. Local paths,
build numbers and toolchain differences can change generated bytes, so compare
source hashes and behavior as well as binary hashes.

## Changes and bounded qualification

The patch preserves source-owned wedge identities and rational MusicXML clocks,
places off-onset wedge endpoints without splitting rhythmic notes, and retains
grace slash identity, chord budget inheritance and explicit decimal playback
allocations through native reload and export. It also includes corresponding
audio encoder/sequencer and Windows WebAssembly build changes.

Twenty-nine original synthetic flows passed, including thirteen exact timing
checks, nine source-owned slur checks and four additional inheritance/dual-side
controls. Twelve broader scores retained written notes, rests, spans, SVG
geometry and edit mapping; thirteen PDF pages were pixel-identical. Eleven MIDI
timelines were unchanged. One changed exactly at four explicit source grace
allocations that the old renderer ignored; all other MIDI events were unchanged.
Three original synthetic WAV exports contained finite, non-silent stereo float
PCM. Waveform timing, Android runtime and paired live deployment remain separate
verification steps. No private score files or phone logs are included here.
